## 1. CURRENT ARCHITECTURE（实际的，不是名称推测的）

### vision-detection（8080，外周视觉，常开）
- `scripts/local_vision_dashboard.py`：YOLOv8n 物体、YuNet 人脸、SFace 识别（arcface 可切）、
  FER+ 表情、MediaPipe 人脸/手部；20 fps 推理。
- 每帧输出 `people[]`：`person_id / role / face_id / body_id / azimuth_deg / elevation_deg /
  distance_m / reflex_area_ratio / gaze_score / lip_motion / emotion_* / identity_similarity`，
  另有 `objects[] / novelty / gestures / person_count`。
- 身份：`stable_person_id(user_id, face_track_id, guest_id)`；认得出用名字，认不出用
  `vision_guest_xxxx`（2026-09-17 新增 `GuestGallery` 人脸模板短期重识别），再不行才用框跟踪 id。
- 接口：`/api/state /api/cameras /api/connect /api/start /api/stop /api/enroll`。
- **没有任何接收自上而下控制的接口**（没有 ROI / 目标类别 / TTL 的入口）。

### voice-detection（8090，外周听觉，常开）
- 采集/VAD/降噪/GCC-PHAT 测向/波束/AEC：`voice_detection/{io,frontend,doa}.py`。
- `AcousticTrack`（`types.py:75`）：`azimuth_deg / overlap_probability / self_echo_probability /
  speaker_label / speaker_similarity / target_speaker_probability / clarity / features / transcript`。
- ASR：Sherpa Zipformer 流式（partial）+ SenseVoice 终句复读（`asr.py`），终句要流式模型佐证。
- 声纹：ERes2NetV2 + `SpeakerProfileStore`（`speaker_embedding.py`）：每身份 embedding 池 ≤8、
  `reference_path`（TSE 参考 wav）、陌生人自动建簇 `stranger_<hex>`；
  2026-09-17 改为可由人脸确认来扩池、陌生人聚类不再压制有名字的人。
- 声学事件：AST 事件/音乐、`bio_acoustics.py`、`acoustic_reflex.py`（惊跳 + 定向，阈值按设备语音峰值推）、
  VAP 轮次预测。
- **已有一个 10 秒 16k 单声道环形缓冲**：`scene_runtime.py` 的 `self.audio = deque(maxlen=500)`，
  但它是喂 AST/VAP 的，不是为聚焦听觉设计的混合音频缓冲（无回看接口、无窗口协议）。
- 目标说话人提取：`target_speaker.py`（因果 SpeakerBeam）+ `multi_speaker.py`
  （句末、≤4 个登记参考、≤12 秒、每路独立验声纹），由 `--tse` 手动选，**不受注意力控制**。
- 接口：`/api/state /api/profiles /api/devices /api/playback /api/start /api/stop
  /api/robot-speaking /api/voice-pool /api/enroll-speaker`。
- **没有接收 AuditoryAttentionTarget 的接口**。

### robot-attention-perception（8092，全局注意力）
- 五个输入源可插拔：`attention_sources.py`（audio_visual / memory_context / linguistic_context /
  cross_session_memory / internal_state），选择存 `.run/attention-config.json`。
- 算法是独立 `.so`，C ABI 见 `include/robot_attention_perception/attention_plugin_abi.h`：
  定长 POD + 通用键值扩展位；候选 id 形如 `visual:<person>` / `audio:<track>`，
  **视觉与听觉各自独立进入，没有第三个 AV 候选**（与指导一致）。
- 竞争层 `src/plugins/attention_common.hpp`：显著度 → 自上而下偏置 → 偏向竞争 →
  除性归一化（v2 乘性注意场 + 跨模态归一化池 κ=0.35）→ 习惯化/IOR/迟滞 →
  交流意愿对数几率（含 2026-09-17 新增的持续对视项）→ 状态机。
- 工作区 `global_workspace.py`：soft-WTA(share=a²/Σa²)、容量 4、urgency≥0.7 抢占、
  订阅/回放/SSE/ROS；**每个感知周期无条件广播**。
- 非感知候选：`memory_candidates.py`（过期未答的问题）、`affect_candidates.py`（持续负面表情）、
  `presence_candidates.py`（2026-09-17 新增：久坐安静）。
- 反射：`reflex_attention.py`（视觉逼近按角尺寸/角速度、声学 startle/orient）。
- 会话门控：`conversation.py` + `interaction_fusion.finalize_gate`，2026-09-17 新增三条
  conversation floor（回答我的问题 / 点名 12 秒窗口 / 唯一被注视者说话）。
- 人物管理：`person_manager.py`，2026-09-17 新增 person_id 连续性与 60 秒身份保留。
- 绑定：`competition_adapter.py` 里按"一张动的嘴 + 一个声音"判定，写入 `binding_notes`；
  **是一次性判定，没有持久的 Bij 置信度状态，也不随聚焦证据更新**。

### hri-memory-service（8788）
- Rust，接口只有三个：`/v1/health`、`/v1/events`（POST 写 / GET 读）、`/v1/search`。
- 事件 kind 实际在用的：`heard_utterance / dialogue_turn / brain_trace / acoustic_track /
  person_observation / attention_state / attention_changed / startle / audio_event / gate_rejected` 等。

### biomimetic-brain-test（8094）
- 消费 `/attention/brain_input` 与 `/attention/workspace`；`attention_trigger.py` 只吃 engagement
  与工作区事件（memory/affect/presence）；`dialogue_continuity.ExpectedAnswer` 记"我问了谁什么"。
- `prompt_context.py` 组织给大模型的上下文（2026-09-17 结构化：相对秒、对话可读、工具说明）。
- `llm.py`：OpenAI 兼容客户端 + 工具循环（`tools.py`：天气、时间）+ 上下文预算裁剪。
- 回灌注意力的目标只有四种：`awaiting_answer / holding_floor / deferred_turn / greet_owner`。

### robo-model（远端 162）
- llama-server + Qwen3.5-9B Q4_K_M，`-c 32768`（2026-09-17 从 4096 改），systemd `robo-qwen9.service`。

## 2. KEEP / EXTEND / ADD / REMOVE

### KEEP（不动）
- vision-detection 的外周视觉全部推理链；voice-detection 的采集/VAD/DOA/波束/AEC/流式 ASR/声学事件；
  hri-memory-service；Brain 的认知决策与 ExpectedAnswer；robo-model。
- 注意力 v2 的显著度/偏置/竞争/归一化/习惯化/IOR/迟滞/交流意愿层与插件 ABI。
- 工作区的 soft-WTA、容量、urgency 抢占。
- 候选与绑定的现有形态（V/A 独立、绑定是关系）——指导要求的这两条本来就已经成立。

### EXTEND（在现有结构上扩）
1. **听觉候选按说话人拆分**：现在音频候选是一条主导声轨，多人同时说话时不会出现并行 A₁/A₂/A₃。
   在 voice-detection 内按声纹嵌入 + 方位做在线说话人聚类，输出多个 `AuditoryCandidate`。
2. **BindingRelation 持久化**：把 `competition_adapter` 的一次性判定升级为带置信度、可被新证据更新的
   `Bij` 表，经 ABI 扩展位进插件（不改结构体布局）。
3. **工作区加 COMMIT_TO_WORKSPACE / SEEK_MORE_EVIDENCE**：现在每周期广播，改为按证据充分度/urgency/超时决定。
4. **Brain goals 增加 `Listen(person)` 与 `Find(object)`**：现有四种目标不足以表达指导里的两个例子。
5. **SpeakerProfileStore 升级为 Reference Speech Bank**：一个身份多份参考，按 SNR/重叠/时长/置信度排序选优。
6. **`_adapt_voice_pool` / `add_verified_sample`**：已按人脸确认扩池（2026-09-17），继续用于自动积累参考。

### ADD（新增，但都挂在现有服务里，不新建 Attention/Brain/Memory）
| 新增 | 落在哪 | 作用 |
|---|---|---|
| `MixedAudioRingBuffer` + 回看接口 | voice-detection | 10~30 秒原始混合音频，支持 pre-roll 回看 |
| `AuditoryAttentionTarget` 接收端 | voice-detection `/api/attention-target` | GA 指定听谁 |
| `SpeakerReferenceResolver` | voice-detection（复用 profiles + memory） | person→speaker→reference |
| `FocusedHearingEngine` | 新进程/服务（162 上） | 封装 Xiaomi 的 `model(mixed, reference)` |
| `StreamingAdapter` | voice-detection | 滑窗 + 重叠 + 假设稳定化 + PARTIAL/FINAL |
| `FocusedAudioEvidence` 上行 | voice→attention | 回灌 GA，不进 Brain |
| `VisualAttentionBias` 接收端 | vision-detection `/api/attention-bias` | GA 指定重点看哪里/找什么 |
| `FocusedVisualEvidence` 上行 | vision→attention | ROI 精细结果回灌 |
| `attention trace / metrics` | attention | 每次切换可追踪 |

### REMOVE（只停用，不删数据）
- `--tse speakerbeam` 的固定 `config/speaker_references/target.wav` 单目标模式：被 GA 驱动的聚焦听觉取代。
- `--tse multi` 的"所有登记人各抽一遍"：保留为离线对照工具，不进实时链路。
- 两者都不删代码，改为不在默认启动路径里。

## 5. 与指导假设冲突的事实（事实优先）

1. **Xiaomi 权重 35.6 GB（fp32）**，bf16 约 17.8 GB。162 两块 4090 当前空余 GPU0 约 11 GB、GPU1 约 4.8 GB，
   **bf16 现在放不下**。三条路：腾出一块 4090、int8 量化（约 9–10 GB，质量影响未知）、
   或降精度/分片。需要用户决定，不能擅自动别人的 GPU 进程。
2. **Mac 本地**：48 GB 统一内存装得下 bf16，但 M4 Pro 上 ~9B SpeechLLM 预计每次 3–5 秒，
   只够离线验证，撑不起 300–800 ms 步进的伪流式；且官方示例是 `.cuda()`，MPS 支持需要实测。
3. **"voice-detection 的 DOA（如果已有）"**：确实有（GCC-PHAT），但只在阵列在位时；
   内置麦克风无方位，绑定与目标选择要能在无方位下退化工作。
4. **"不要要求用户手动准备 reference.wav"**：现状已有自动保存参考的路径（`save_tse_reference`），
   但触发挂在声纹自学习上；2026-09-17 已把自学习改为人脸确认驱动，参考积累随之能跑起来。
5. **Brain Goal**：现有只有 awaiting_answer / holding_floor / deferred_turn / greet_owner，
   指导里的 `Listen(Person17)` 与 `Find(red cup)` 需要新增，不是现成的。
6. **工作区**：目前每周期无条件广播，不存在 COMMIT/SEEK 决策，第 3 步是真的新增。
7. **多人并行听觉候选不存在**：这是第 5 步的实质工作量所在，也是 Xiaomi 能否发挥作用的前提——
   没有它，Xiaomi 只能对着唯一一条主导声轨做抽取，等价于现在的 speakerbeam 模式。
